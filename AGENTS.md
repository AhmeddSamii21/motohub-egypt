# Project instructions — MotoHub Egypt (`MotoHub-Egypt-Portfolio`)

Read `HANDOFF.md` in this project root before any other work. It is the persistent source of truth for the current project state.

## HANDOFF.md maintenance policy

- `HANDOFF.md` is the persistent source of truth for the current MotoHub project state.
- Update it after meaningful milestones: completed features, important test results, architectural or business decisions, blockers or plan changes, commits, and deployments.
- Do not update it after every ordinary chat message or trivial exchange.
- Update only the relevant sections. Preserve unrelated information; never rewrite the whole file for a small change.
- Record: what changed, which files were affected, verified test results (with evidence), important limitations, and the next recommended task.
- Never claim that a test, feature, deployment, or external integration was verified unless there is evidence (command output, API response, or recorded result).
- Do not change application code merely to update the handoff.
- Keep updates concise to minimize context and token usage.
- At the end of each meaningful development task, report briefly: what changed, tests and results, whether `HANDOFF.md` was updated, and the next recommended step.
- Before a session or model handoff, ensure the important project state is recorded in `HANDOFF.md`.
- Do not promise automatic execution of this or any other policy at every milestone unless a configured mechanism actually guarantees it — this document is guidance OpenCode loads as instructions, not an enforcement mechanism.
